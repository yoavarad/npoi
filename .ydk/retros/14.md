## AI Analysis
### Patterns
- Tooling friction dominated the epic: roughly half of the tasks (166, 165, 136, 33, 32, 31, 27, 26) concerned the ydk task/verification tooling, its hooks, config, or caching rather than product code.
- Recurring ydk defects share a root cause of hard-coded assumptions: base branch 'main' assumed instead of the repo default (32), verification cache keyed on *.py only (136), dotnet plugins run on docs-only changes (33), and active-task.json resolved relative to the working checkout rather than the main checkout (165).
- Verification and caching correctness issues: caching failures and replaying stale results (136) led to a content-keyed cache in 1.5.0 (166), showing a bug fix followed by a docs update to capture the quirks.
- Fix-then-document loop: tool fixes were followed by rules/docs updates (166 after 136), indicating knowledge capture is happening, but after the fact.
- Flaky test cluster: 68 (sub-second seed time vs rounded formatting) and 66 (Windows file locks from FileShare.None) are environment/timing-sensitive failures; both come from non-determinism (time precision, OS file-locking semantics) rather than logic errors.
- Foundation and hygiene work was front-loaded: .NET 10 SDK pinning (24), .NET 10 verification (25), verification plugins (26), YDK config (27), branch rename (28), graphify (29), CLAUDE.md (30), and a repo-wide dotnet format (46) establish baseline conventions before feature work.
- Analyzer and warning cleanup (50: CA2022 re-enabled, test warnings cleared) combined with a repo-wide format (46) indicates a push toward enforced code-quality gates; ordering matters because format-all should land before or isolated from functional changes to avoid noisy diffs.
- Branch rename master->main (28) directly exposed hard-coded branch assumptions in tooling (32), a cross-task ripple effect.
- Worktree/multi-checkout awareness gaps (165) show hooks break when run from non-main checkouts.

### Template suggestions
- Flaky test fix template: test name, failure mode (timing / file lock / ordering / environment), platform(s) affected, root cause category, deterministic fix applied, and how repeated runs (N iterations, Windows + Linux) were used to confirm stability.
- Tooling bug report template for ydk: version, command run, expected vs actual behavior, assumptions violated (branch name, file types, checkout location), and a regression test or repro steps.
- Verification cache change checklist: cache key inputs (all relevant file types, content hash, tool version), whether failures are cached, invalidation triggers, and a stale-result test.
- Repo-wide mechanical change template (e.g., dotnet format, analyzer re-enable): scope, tool and version, isolation in a dedicated commit/PR, instructions for ignoring in git blame (.git-blame-ignore-revs), and rebase guidance for open branches.
- Environment bootstrap/upgrade checklist: SDK pin (global.json), hooks regenerated, verification plugins target the right solution, CLAUDE.md/README/AGENTS.md refreshed, and the default branch confirmed.
- Post-fix docs follow-up template: for any ydk fix that changes behavior, an accompanying quirks/rules doc update line item in the same task.

### Rule suggestions
- When a tool fix changes observable behavior (cache keying, plugin selection, branch detection), update the relevant rules/quirks docs in the same task or PR rather than a follow-up.
- Never hard-code branch names; resolve the default branch from the repo (origin/HEAD) and add a test using a non-'main' default branch.
- Verification caches must key on content hashes of all inputs including tool version, and must never cache failures; add a stale-result regression test for any cache change.
- Skip dotnet verification plugins on docs-only changes and report skipped plugins as SKIPPED, not FAIL, in PR bodies.
- Hooks and scripts must resolve shared state (e.g., active-task.json) from the main checkout via git-common-dir so they work from any worktree.
- Tests must not depend on sub-second timing or rounded time formatting; use fixed/injected clocks or tolerance, and open shared test data files with FileShare.Read (or copy to temp) to avoid Windows locks.
- Land repo-wide formatting or analyzer re-enable changes in isolated PRs, add the commit to .git-blame-ignore-revs, and merge them before or after, not mixed with, functional changes.
- After any default-branch rename or similar infrastructure change, run a checklist audit of hooks, CI, tooling config, and docs for stale references.
- Do not suppress analyzer warnings (e.g., CA2022) to pass; fix the root cause and keep the analyzer enabled, treating test warnings as errors in CI once cleared.
- Pin tool/SDK versions (global.json, ydk version) and regenerate hooks after any upgrade, removing local workarounds in the same change.
