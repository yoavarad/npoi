## AI Analysis
### Patterns
- POIFS robustness theme: tasks 35, 58, 149 and 135 form a chain in which an initial gap-closing effort (#35) led to follow-ups (#58) and then to regressions or edge cases (#149) tied to file open modes.
- Open-mode side effects: #135 (read-only unless a write is requested) and #149 ('Potential loop detected' after opening POIFS with readOnly:false, then HSSFWorkbook) suggest that changing default access modes exposed interactions between POIFS and HSSFWorkbook that were not covered by tests.
- Collection-contract and encapsulation bugs: #34 (HSSFWorkbook/DirectoryNode collection contracts) and #57 (Add/Insert/indexer-set bypassing the internal workbook) are the same class of defect, where collection operations skip validation or internal state sync.
- Resource lifecycle leaks: #115 (unclosed read-back workbook in a test) and #135 (read-only file handles) both concern resource handling and file-handle ownership.
- Follow-up debt: #58 is an explicit follow-up from #35, and #36 fills 'remaining' gaps, which suggests the original scope was incomplete and needed several passes.
- Foreign-object rejection: #115 and #57 both involve sheets from another workbook being added or inserted, an edge case that repeatedly needs guard checks.
- Regression sequence: a bug filed after a behavior change (#149 after #135) suggests the change shipped without cross-component tests.

### Template suggestions
- Bug report template for I/O issues: file/stream open mode (readOnly true/false), the sequence of API calls, the exact exception text, and a minimal repro file.
- Robustness/gap-closing task template: scope checklist (readers, writers, edge cases), explicit 'out of scope' list, and a planned follow-up ticket link so that remaining gaps are tracked up front.
- Collection-contract test template: for every collection-like API, cover Add, Insert, indexer-set, Remove, Clear, enumeration, null input, duplicate input, and foreign-owner input.
- Behavior-change checklist: when changing defaults such as access modes, list affected components, run the cross-component open/modify/save matrix, and document the migration note.
- Test resource-cleanup template: every test that opens or reads back a workbook or POIFS uses a using/try-finally or dispose pattern.

### Rule suggestions
- Any change to default file or stream access mode must include tests for every open mode (read-only and writable) combined with each downstream consumer (POIFS, HSSFWorkbook, HPSF).
- Every collection-like API on HSSFWorkbook or DirectoryNode must have a contract test covering Add, Insert, and indexer-set, and all paths must go through the same validation and internal-state update.
- Tests must dispose or close any workbook, POIFS filesystem, or stream they open, and a leak check (e.g. analyzer rule or CI warning) should enforce it.
- Reject objects belonging to a different workbook or filesystem at all entry points, with a consistent exception type and message.
- When closing a robustness epic, require a 'remaining gaps' review before sign-off so follow-up tickets are created and linked rather than discovered later.
- Add a regression test to the originating ticket for every bug caused by a prior sprint's change, and link the two tickets.
- Loop or cycle detection errors must include diagnostic context (open mode, block or sector index) to ease triage.
